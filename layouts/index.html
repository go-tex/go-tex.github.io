Genuine LaTeX classes, in pure Go

go-tex is a pure-Go (CGO_ENABLED=0) TeX effort. Its engine is a faithful re-implementation of TeX — the category-code mouth and gullet, a scaled-point stomach with Knuth–Plass line breaking and a cost-based page builder, \halign tables, math, OpenType fonts, and PDF/SVG output — and on top of it, it loads and runs the genuine LaTeX classes: \documentclass{article}, {report} and {book} execute the real, embedded .cls files (LPPL, verbatim) — not an emulation. They typeset a numbered title, a dotted \tableofcontents, numbered sections, \chapter, numbered figure/table captions, lists, and math.

Because the class files are embedded and the resolver needs no filesystem, the real classes also run in the browser via js/wasm — genuine LaTeX class rendering client-side, with no TeXLive and no server.

Capabilities

A full pipeline, gated by objective oracles.

Real base classes

article, report and book load and run the genuine embedded LaTeX .cls files — numbered title, dotted TOC, numbered sections/chapters, figure/table captions, lists, math.

Faithful engine

Category-code mouth and gullet, a scaled-point stomach with Knuth–Plass line breaking, a cost-based page builder, and \halign tables.

Math & fonts

Math via go-tex/math (vector output); OpenType fonts with a built-in default font, kerning and ligatures — runs with no assets, and a full family (roman, bold, italic, slanted, typewriter, sans) when one is given.

PDF & SVG output

Embedded-subset-font PDF with selectable text, and self-contained SVG pages carrying a source map for click-to-line.

In the browser

A self-contained js/wasm build renders real LaTeX classes client-side — no TeXLive, no server.

Safe on untrusted input

A .tex is a program, and the playground runs whatever you paste. A document compiled by the engine cannot run a process (TeX’s \write18 has no implementation here), cannot write a file, and cannot read one outside the search roots — TeX Live’s openin_any=p, with GOTEX_READ_ANY=1 as a named opt-out. The first two are asserted by a scan of the package’s own source, since no API could express them. Fonts and images still load by absolute path, on purpose: each decodes its file, so a path that is neither puts nothing on the page. It also cannot exhaust memory or run forever: one paragraph is capped (200 000 nodes, against a largest-real-paragraph of 8 881 measured over the fidelity corpus) and the run ends as TeX’s capacity error does; and no word longer than 63 letters is hyphenated, which is TeX’s own limit and where 98.6% of the time was going.

Held to fidelity

A byte-exact conformance ratchet plus a whole-document prose check against a real LaTeX engine (tectonic): on 154 real arXiv papers the median is 101% of the reference’s prose words, with 10 of them below 95%. Above 100% is expected, not flattering — each formula’s source is emitted as an invisible text layer so the maths can be found and read aloud, and the word census counts it.

Scope

The engine loads and runs the standard base classes — article, report, book and now amsart as real embedded files — and any resolvable .cls/.sty runs as real TeX macros. It is functional-parity-oriented and held to real-LaTeX fidelity, not a claim of full TeXLive parity: heavy drawing (tikz/pgf) is gated and still in bring-up, biblatex is partly supported (Biber’s data .bbl is parsed and typeset — 30 of 30 and 15 of 17 titles present on the two corpus papers that ship one — while its citation commands and styles are not modelled), PDF figures need the pdfrender module, and floats typeset inline unless placement is enabled. Every supported feature — and every remaining gap — is listed in the capability reference.
